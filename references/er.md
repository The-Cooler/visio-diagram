# ER Diagram

通用规则见 `SKILL.md` 的「1. 确定画什么」「2. 确定依据」「3. 生成」。本文件只写 ER 特有的内容。

## 能画的范围
只能画单实体属性图：一个实体加 1–10 个属性（含一个主键）。没有系统 E-R 图模板，多实体之间的连线画不了。

判断图能否画，看图题和内容：实体属性图、表结构可画；系统 E-R 图、实体关系图（多实体加关系）不可画；类图、用例图不属于 ER。

数“第几张实体属性图”时，计数集合先按“可画”筛一遍，系统 E-R 图不占号。例如 3-1、3-2 是系统 E-R 图、3-3 起是实体属性图，可画集合是 3-3、3-4、3-5…，第三张是 3-5。图号仍用论文原编号，不重编。

## 依据论文时的额外一步
`SKILL.md` 已说明有论文就读文字、无论文用描述或 SQL。ER 不同之处是还要问一次「是否根据该论文生成 ER 图？」：

- 是 → 从论文文字取实体、属性、主键（字段表、正文描述）。论文里的系统 E-R 图只能用来核对实体名和字段名，不要复原它的连线。
- 文字里缺字段表、只有实体名或没有主键时不要自行补全：告诉用户「当前论文缺少生成 ER 图所需的实体与字段证据」，并询问能否提供 SQL 建表文件。给了 SQL 就按 SQL 生成；仍要求只用论文，就只画明确写出的字段并说明缺了什么。
- 否 → 用用户描述或 SQL。

## JSON
```json
{
  "entity": "用户",
  "attributes": [
    {"name": "用户ID", "type": "pk"},
    {"name": "用户名"},
    {"name": "创建时间"}
  ]
}
```
没有 `title` / `template` 字段，模板由属性数量决定。

## 入口
没有 check / verify / set-text，只有 CLI 入口（内部先校验再调用 `er_draw`）：

```bash
# 在 skill 目录执行
python -m scripts.er <项目根>/json/er/<实体>.json [--project-root <项目根>]
```

JSON 放在 `<项目根>/json/er/`，输出到 `<项目根>/draw/er/`。省略 `--project-root` 时使用当前工作目录。

## 属性规则
- 1–10 条，超过会被校验拒绝。
- 最多一条 `type: "pk"`，主键排第一行。
- 实体名和属性名需含中文，`id` / `ID` 例外。
- 属性少于 10 条时多余的形状会被删除，不留空行。

## 模板与输出
- 按属性数奇偶选模板：奇数 `ER_odd.vsdx`，偶数 `ER_even.vsdx`，两者只是版面对称。
- 输出到 `draw/er/<实体>.vsdx`。
- 没有覆盖保护，同名文件会被直接替换；调用前先看目标是否存在。
