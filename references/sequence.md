# Sequence Diagram

通用规则见 `SKILL.md` 的「1. 确定画什么」「2. 确定依据」「3. 生成」。本文件只写时序图特有的内容。

## 依据论文
按 `SKILL.md` 的「2. 确定依据」先确定论文。从文字里提取每条消息（接口/调用说明），论文里嵌的时序图不解析——那张图正是要重画的对象。论文只写结果性描述（如「调用检索接口」）而没有中间层时，不要自行补中转调用。

## 选模板
用户点名“第 N 张时序图”时，先按正文顺序把时序图列全再对号；列不出来就说无法确定并请用户直接给图号，不要凑一个看似接近的图号。

读完目标时序图对应的正文之后，再用 `AskUserQuestion` 问模板。只看目录、标题或图号就问泳道架构，会让用户在信息不足时作答，后面还得返工。

读完论文里目标时序图对应的正文之后，再用 `AskUserQuestion` 问模板。只看目录、标题或图号就问泳道架构，会让用户在信息不足时作答，后面还得返工。

每个选项的 description 写出泳道，用户才能按架构判断。一个问题最多 4 个选项，而模板有 6 个，所以分两步，先运行 `python -m scripts.sequence.tools templates` 拿清单：

1. 问架构，4 个选项：
   - `Spring Boot 分层` — 管理员/前端/控制器 + 服务层或 Mapper + 数据库
   - `Python 分层` — 用户/前端/路由层 + 服务层/仓储层/存储层
   - `通用四泳道（服务层）` — 管理员/前端/服务层/数据库，14 条，Spring Boot 与 Python 都能用
   - `通用四泳道（控制器）` — 推荐。管理员/前端/控制器/数据库，14 条，Spring Boot 与 Python 都能用
2. 选了 Spring Boot 或 Python 再问层数：
   - `五层（18 条）` — 管理员/前端/控制器/服务层/数据库（Python 为路由层）
   - `六层（22 条）` — 再加 Mapper（Python 为仓储层/存储层）
3. 选通用四泳道直接对应 template_6 / template_7，不用第二步。

模板清单：

| Template | 名称 | 泳道 | 消息数 | 说明 |
|---|---|---|---|---|
| template_1 | Spring Boot 六层 | 管理员/前端/控制器/服务层/Mapper/数据库 | 22 | 含 Controller、Service、Mapper |
| template_2 | Python 六层 | 用户/前端/路由层/服务层/仓储层/存储层 | 22 | 含 Router、Service、Repository、Storage |
| template_4 | Spring Boot 五层 | 管理员/前端/控制器/服务层/数据库 | 18 | 省去 Mapper |
| template_5 | Python 五层 | 管理员/前端/路由层/服务层/数据库 | 18 | 省去仓储层/存储层 |
| template_6 | 通用四泳道（服务层） | 管理员/前端/服务层/数据库 | 14 | 最简四泳道，语言无关 |
| template_7 | 通用四泳道（控制器） | 管理员/前端/控制器/数据库 | 14 | 推荐，最简四泳道，语言无关 |

不要替用户默认选模板；即使用户描述了架构，也让用户确认一次。

## 泳道名称替换
两条泳道标题按图的业务语境改写，其他泳道保持原样：

- **第一泳道**用 `role`，写这张图里的实际操作者，取值由图的描述决定，不限于模板默认的「管理员」或「用户」。
- **第二泳道（前端）**用 `frontend_lane`，写具体前端页面名（如「课程管理页面」），不能仍是「前端」，最多 8 个字——泳道标题空间有限，超出会被挤压。
- 两个字段都必须显式填写；`check` 只拒绝缺省、空值或含换行，不限制 `role` 的具体取值，角色本来就叫「管理员」时照填即可。
- `draw` 只改这两个泳道形状的文字，冒号前缀、字号、位置、连接线和其他泳道都不动；`verify` 会读回核对。

## JSON
```json
{
  "title": "课程查询时序",
  "template": "template_6",
  "role": "教师",
  "frontend_lane": "课程管理页面",
  "messages": [
    {"from": "管理员", "to": "前端", "text": "查询课程"},
    {"from": "前端", "to": "服务层", "text": "请求列表"}
  ]
}
```
`messages` 的条数和每条 `from -> to` 要与下方对应模板的 Flow 逐条一致。`from` / `to` 仍写模板里的泳道名（第一泳道写「管理员」或「用户」，前端写「前端」），只有泳道标题会被替换。

## 内容约束
- 每条消息不超过 6 个字（`SEQUENCE_TEXT_MAX_LEN = 6`），且非空。消息文字挤在箭头旁，超出会压住相邻元素，脚本用 `len()` 判定而不是目测。
- `template/sequence/*.vsdx` 是共享原件，`draw` 会复制后再编辑；直接改原件会让之后每次绘图都继承改动。

## 输出
JSON 放 `json/sequence/<title>.json`，输出 `draw/sequence/<title>.vsdx`。
